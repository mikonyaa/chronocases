# Report result invariants

Reports still use schema version 1. Structural validation and JSON byte/depth/string limits run before the same pure semantic validator used by execution and browser import. Imported data is rejected rather than repaired or relabeled.

- `provenance.corpusVersion` and `corpusHash` identify the installed frozen corpus. Every result has one unique known case ID, the original contract/version, input validity, exact literal input and exact frozen expected outcome. `result.expected` and `fixture.expected` both match that corpus. Display annotations such as titles may be edited; they are never the oracle. The hash is a checksum identifying the corpus, not a digital signature of a report or proof of execution.
- PASS means a valid normalized actual equals the frozen expected and carries a null result reason code. A declared unsupported-transition rejection is UNSUPPORTED even when it matches its negative self-test.
- FAIL means a shape failure or a valid unequal outcome. `reasonCode: INVALID_RETURN_SHAPE` records that the original return was invalid before JSON serialization. Its bounded JSON preview can look valid after IPC (for example a rich date object or extra undefined field); that telemetry takes precedence. An imported report cannot establish the pre-serialization history independently.
- ADAPTER_ERROR records a supported operational code and null actual. Timeout/log/result limits, crashes and throw/rejection are operational errors. They never stand for a exhausted recurrence window.
- UNSUPPORTED_ENVIRONMENT and MISSING_ADAPTER_EXPORT have null actual. UNSUPPORTED_RECURRENCE_TRANSITION requires a valid normalized declined-transition outcome. INTERRUPTED has null actual and its explicit reason code.
- `logs.truncated` is true exactly for ADAPTER_LOG_LIMIT. The shared stdout/stderr budget counts 65,536 raw bytes before decoding; one UTF-8 StringDecoder per stream preserves split characters. Capture is sealed on EOF, cancellation, timeout or limit; late chunks retain no further data. An incomplete UTF-8 suffix is flushed once as U+FFFD. Invalid UTF-8 cannot be preserved as Unicode text; complete valid UTF-8 is preserved byte for byte. The raw-byte budget is independent of the length of the resulting JSON encoding.
- Selected count and all status totals come from the results; selectedContracts is the unique contract list in canonical order. Exit precedence is INTERRUPTED 130, then operational error 2, then unsupported 3, then FAIL 1, otherwise PASS/empty report 0. Thus a full buggy demo retains exit 3 because its explicit unsupported case takes precedence over its 16 failures. The `demo` command itself exits 0 when its reports have been created.

The existing format records the declared count and included IDs rather than a separate original selection manifest. Removing a result while retaining its declared count is invalid. A coherent smaller subset is still a valid subset report; version 1 cannot prove that an omitted case was originally selected. An empty imported report remains readable, while CLI run rejects an empty selection.

Both embedded reports are validated before enabling demo switches. Malformed embedded JSON or contradictory data displays a readable error with Open report recovery. A failed file import retains the previously opened valid report. Download is disabled until a valid report is available. Arbitrary invalid actual previews are displayed as text without being interpreted as normalized outcomes.

Logs and display text preserve dollar syntax and both template markers. JSON escapes `<`, U+2028 and U+2029; one callback replacement pass embeds data/script without interpreting dollar replacement syntax or reprocessing markers introduced by logs. The offline CSP is unchanged. The CLI does not open a browser automatically.
